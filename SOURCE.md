# Паспорт источника: GH Archive (публичные события GitHub)

## Доступ

- **Поток**: почасовые архивы `https://data.gharchive.org/<YYYY-MM-DD>-<H>.json.gz`,
  H — 0..23 без ведущего нуля. Новый файл появляется после окончания часа.
- **История**: те же файлы, сплошь с 12.02.2011.
- **Глубина истории**: с 12.02.2011.
- **Схема истории**: те же события и ключ, что у потока; пропуск закрывается
  повторной загрузкой часового архива за пропущенные часы.

## Лицензия и условия использования

- Код проекта — MIT; материалы сайта — CC BY 4.0; события — публичные данные
  GitHub, условия — GitHub Terms of Service.
- Собранные данные остаются на стенде студента, не публикуются.

## Лимиты и представление клиента

- Объявленных лимитов нет; файлы загружаются по одному.
- **User-Agent**: `bigdata-stand/1.0 (an.mordin@gmail.com)`.
- Опрос — не чаще одного раза в `COLLECTOR_POLL_SECONDS` (по умолчанию 300 с).
- 429/5xx и сетевые ошибки — повтор с растущей паузой; 404 — ожидание
  публикации файла, позиция не сдвигается.

## Схема события

| Поле         | Тип                       | Смысл                     | Пример                        |
| ------------ | ------------------------- | ------------------------- | ----------------------------- |
| event_key    | string                    | id события GitHub, ключ   | "12345678901"                 |
| event_time   | timestamp (ISO 8601, UTC) | created_at события        | "2026-01-12T10:00:01Z"        |
| received_at  | timestamp (ISO 8601, UTC) | время получения сборщиком | "2026-01-12T12:00:05.123Z"    |
| source       | string                    | значение оси SOURCE       | "github"                      |
| type         | string                    | тип события GitHub        | "PullRequestEvent"            |
| action       | string                    | действие в payload        | "opened", "closed", "created" |
| actor_login  | string                    | логин автора              | "octocat"                     |
| repo_name    | string                    | полное имя репозитория    | "owner/repo"                  |
| org_login    | string                    | организация (если есть)   | "kubernetes"                  |
| pr_number    | int (nullable)            | номер PR                  | 42                            |
| pr_id        | bigint                    | идентификатор PR          | 987654321                     |
| pr_state     | string                    | состояние PR              | "open", "closed"              |
| pr_merged    | bool                      | был ли PR слит            | false                         |
| public       | bool                      | публичный ли репозиторий  | true                          |
| review_state | string (nullable, v2)     | состояние review          | "approved"                    |

- **Ключ события**: `id`, уникален в пределах всего архива GitHub.
- **Время события**: `created_at`, UTC, точность до секунды.
- `review_state` есть только у `PullRequestReviewEvent` и принимает значения
  `approved`, `changes_requested`, `commented`, `dismissed`; у
  `PullRequestEvent` и `PullRequestReviewCommentEvent` поля `review` в payload
  нет, значение `null`. Поле введено в v2 схемы (ЛР2), сборщик извлекает его
  с 2026-10-25 20:51 UTC.

## Фильтр потока и объёмы

- **Фильтр задания**: `PullRequestEvent,PullRequestReviewEvent,PullRequestReviewCommentEvent`.
- **Интервал наблюдения**: 2026-10-22 22:00 — 2026-10-23 22:00 UTC (24 ч, 24 файла).
- Доля `kept` по интервалу: **37.07%** — аномально высокая, см. «Известные дефекты».

|                           |  До фильтра | После фильтра |
| ------------------------- | ----------: | ------------: |
| событий в минуту          |        84.3 |          31.3 |
| байт в сутки до сжатия    | 485 330 977 |    15 369 061 |
| байт в сутки после сжатия | 102 220 490 |     1 873 327 |

> «До фильтра» — исходные файлы GH Archive (gzip источника).
> «После фильтра» — наш нормализованный слой `stream/` (gzip).
> Байт на событие: ~3 996 у источника (полный `payload`) против ~341 у нас
> (14 полей). Поток до фильтра сборщик не хранит, поэтому в его клетке —
> сжатие источника, а не наше.

- **Восемь недель потока** после фильтра и сжатия: **56 × 1.87 МБ ≈ 105 МБ**
  при текущем (аномальном) темпе; при курсовом темпе ~170 kept/мин —
  **56 × 10.2 МБ ≈ 570 МБ**.
- **Исторический срез 7 суток**: **15 МБ**.
- **Слой сырых данных целиком**: **~120 МБ** при пределе `COLLECTOR_RAW_LIMIT_GB=20` ГБ.
- **Первое ограничение при росте потока — диск**. При росте в 1000 раз слой
  составит 105–570 ГБ, в 5–28 раз больше предела; ротация начнёт удалять
  данные раньше восьми недель. Решения: увеличить предел и/или писать Parquet
  вместо JSONL. Вторичное ограничение — обход `rglob` в `enforce_limit()`
  при миллионах файлов.
