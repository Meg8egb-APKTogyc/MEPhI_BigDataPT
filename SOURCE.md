# Паспорт источника: GH Archive (публичные события GitHub)

## Доступ

- адрес потока: почасовые архивы https://data.gharchive.org/<YYYY-MM-DD>-<H>.json.gz
  (H — 0..23 без ведущего нуля); новый файл появляется после окончания часа
- адрес исторического среза: те же файлы, сплошь с 12.02.2011
- глубина доступной истории: с 12.02.2011
- схема истории: те же события и ключ, что у потока; пропуск закрывается
  повторной загрузкой часового архива за пропущенные часы

## Лицензия и условия использования

- код проекта — MIT; материалы сайта — CC BY 4.0;
  события — публичные данные GitHub, условия — GitHub Terms of Service
- собранные данные остаются на стенде студента, не публикуются

## Лимиты и представление клиента

- объявленных лимитов нет; файлы загружаются по одному
- User-Agent: bigdata-stand/1.0 (an.mordin@gmail.com)
- опрос — не чаще одного раза в COLLECTOR_POLL_SECONDS (по умолчанию 300 с)
- ответы 429/5xx и сетевые ошибки — повтор с растущей паузой (2^n, 4 попытки
  в `fetch_hour`), затем `give_up_hour` и `hour_not_ready` с паузой
  `COLLECTOR_POLL_SECONDS`

## Схема события (поля, которые сохраняем)

| Поле        | Тип                       | Смысл                                                                                                                           | Пример                        |
| ----------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| event_key   | string                    | id события GitHub, ключ                                                                                                         | "12345678901"                 |
| event_time  | timestamp (ISO 8601, UTC) | created_at события, время события                                                                                               | "2026-01-12T10:00:01Z"        |
| received_at | timestamp (ISO 8601, UTC) | время получения события сборщиком                                                                                               | "2026-01-12T12:00:05.123Z"    |
| source      | string                    | значение оси SOURCE                                                                                                             | "github"                      |
| type        | string                    | тип события GitHub                                                                                                              | "PullRequestEvent"            |
| action      | string                    | действие в payload                                                                                                              | "opened", "closed", "created" |
| actor_login | string                    | логин автора                                                                                                                    | "octocat"                     |
| repo_name   | string                    | полное имя репозитория                                                                                                          | "owner/repo"                  |
| org_login   | string                    | организация (если есть)                                                                                                         | "kubernetes"                  |
| pr_number   | int (nullable)            | номер PR; null у review-событий, если поле пришло только в `payload.pull_request.number`, и у старых данных до фикса 25.10.2026 | 42                            |
| pr_id       | bigint                    | идентификатор PR                                                                                                                | 987654321                     |
| pr_state    | string                    | состояние PR                                                                                                                    | "open", "closed"              |
| pr_merged   | bool                      | был ли PR слит                                                                                                                  | false                         |
| public      | bool                      | публичный ли репозиторий                                                                                                        | true                          |

- ключ события: `id`, уникален в пределах всего архива GitHub
- время события: `created_at`, UTC, точность до секунды

## Фильтр потока и объёмы

- фильтр задания: PullRequestEvent,PullRequestReviewEvent,PullRequestReviewCommentEvent
- интервал наблюдения: 2026-10-22 22:00 — 2026-10-23 22:00 UTC (24 ч, 24 файла)

|                           | До фильтра | После фильтра |
| ------------------------- | ---------: | ------------: |
| событий в минуту          |       84.3 |          31.3 |
| байт в сутки до сжатия    | 15 369 061 |    15 369 061 |
| байт в сутки после сжатия |          — |     1 873 327 |

- доля kept по интервалу: 37.07% (аномально высокая, см. «Известные дефекты»)
- восемь недель потока после фильтра и сжатия: 56 × 1.87 МБ ≈ **105 МБ**;
  исторический срез 7 суток: **15 МБ**; **слой сырых данных целиком:
  ~120 МБ** при пределе COLLECTOR_RAW_LIMIT_GB=20 ГБ
- ограничение, которое наступит первым при росте потока: **диск**.
  Сейчас 1.87 МБ/сутки × 56 ≈ 105 МБ потока + 15 МБ среза ≈ 120 МБ
  (≪ 20 ГБ). При росте в 1000 раз слой = **~120 ГБ**, в 6 раз больше
  предела — ротация начнёт удалять данные раньше восьми недель.
  Решения: увеличить COLLECTOR_RAW_LIMIT_GB и/или писать Parquet
  вместо JSONL (сжатие ×5–10). Вторичное узкое место — `enforce_limit()`
  обходит всё дерево `data/raw/` через `rglob`, при миллионах файлов
  листинг станет медленным.

## Известные дефекты

- часть часовых файлов неполна (размер в разы меньше соседних) — повторная
  загрузка после публикации
- файл часа появляется с задержкой — сборщик ждёт до появления (404 → пауза)
- 90 % событий — PushEvent, наш фильтр оставляет ~5–10 % потока
- в загруженном архиве встречаются события вне фильтра задания — отбрасываются
  сборщиком по полю type
- источник регулярно дублирует `id` в пределах одного часового файла.
  18.10.2026 08:00 UTC: `id=17520576311`, `kiran8688`, PullRequestEvent,
  `created_at=08:00:40Z` — дважды в одном файле (проверено
  `curl data.gharchive.org | gunzip | jq`). В догоне 22.10 сборщик
  отбросил по одному повтору в часах 19.10 07:00 и 19.10 08:00
  (`dedup_in_file dups=1`). Сборщик отбрасывает повторы по `event_key`
  внутри часа (`seen_keys`); в слое `stream/` дублей нет (проверено
  `uniq -d` — 0)
- **14.10.2026 14:00–22:00 UTC**: часовые файлы источника в разы меньше
  соседних (6–12 МБ против 15 МБ); проверено `curl -I` по файлам
  2026-10-14-12/15/19/22. Фильтр PullRequest\* сохранил обычный объём
  (2–3 тыс. событий/час), потеряны преимущественно PushEvent. На данные
  практикума не повлияло, но для пересчёта объёмов по сырью интервал
  считается аномальным
- **14.10.2026 14:00 UTC**: всплеск доли PullRequest-событий
  (10.7% против 1.7%). Причина не установлена, обработан как обычные
  данные, без фильтрации
- **22.10.2026 22:00 — 23.10.2026 22:00 UTC**: GH Archive публикует
  неполные часовые файлы — 3–5 МБ вместо обычных 30–50 МБ (проверено
  `curl -I` по 2026-10-22-23 / 2026-10-23-12 / 2026-10-23-21 и
  `curl -o /dev/null` по 2026-10-23-0: `http=200, size=3 061 536`).
  Аномалия та же, что 14.10: raw в минуту 84 вместо 170–250, доля kept
  37% вместо обычных 5–10%. На 24-часовой интервал шага 10 это влияет —
  числа занижены, но интервал полный (24 файла на месте), для ЛР2–ЛР9
  данные пригодны
